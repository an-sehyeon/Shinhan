
    1) 자료 구조의 분류 
        - 선형 구조 
            1) 리스트 : 선형 리스트, 연결 리스트
                (1) 선형 리스트
                    - 배열과 같이 연속되는 기억 장소에 저장되는 리스트
                    - 가장 간단한 데이터 구조 중 하나로 데이터 항목을 추가/삭제하는 것이 불편.

                (2) 연결 리스트
                    - 노드의 포인터 부분을 서로 연결시킨 리스트로 연속적인 기억 공간이 없어도 저장이 가능.
                    - 노드의 삽입/삭제가 용이하며 포인터를 위한 추가 공간이 필요하므로 기억 공간이 많이 소요된다.

            2) 스택
                - 리스트의 한쪽 끝에서만 자료의 삽입과 삭제가 이루어지는 자료 구조.
                - 가장 나중에 삽입된 자료가 가장 먼저 삭제되는 후입선출(LIFO) 방식.
                [스택 가드] : 메모리상에서 프로그램의 복귀 주소화 변수 사이에 특정 값을 저장해 두었다가 그 값이 변경되었을 경우 오버플로우 상태로 가정하여
                            프로그램 실행을 중단하는 기술.

            3) 큐
                - 자료의 삽입 작업은 선형 리스트의 한쪽 끝에서, 삭제 작업은 다른 쪽 끝에서 수행되는 자료 구조.
                - 가장 먼저 삽입된 자료가 가장 먼저 삭제되는 선입선출(FIFO) 방식.
                - 운용체제의 잡업 스케줄링 등에서 응용된다.

            4) 데크
                - 자료의 삽입과 삭제가 리스트의 양쪽 끝에서 이루어지므로 두 개의 포인터를 사용하는 자료 구조.
                - 스택과 큐를 복합한 형태.
        
        - 비선형 구조
            1) 트리
                - 그래프의 특수한 형태로써 노드와 가지를 이용하여 사이클을 이루지 않도로 구성한 자료 구조.
                이진 트리의 운행법
                    - 전위 운행 : Root -> Left -> Right
                    - 중위 운행 : Left -> Root -> Right
                    - 후위 운행 : Left -> Right -> Root

            2) 그래프

    2) 스키마의 3계층
        1) 외부 스키마 
            - 사용자나 응용 프로그래머가 접근할 수 있는 정의를 기술.
        
        2) 개념 스키마 
            - 데이터베이스 전체를 정의한 것으로 데이터 개체, 관계, 제약조건, 접근 권한, 무결성 규칙 등을 명세한 것.
            - 범기관적 입장에서 데이터베이스를 정의한다.

        3) 내부 스키마 
            - 데이터의 실제 저장 방법을 기술.
            - 물리적 저장 장치의 입장에서 본 데이터베이스 구조러써 실제로 데이터베이스에 저장될 레코드의 형식을 정의하고 저장 데이터 항목의 표현 방법,
                내부 레코드의 물리적 순서 등을 나타낸다.

    3) 데이터 베이스 언어
        1) DDL(Data Definition Language) 
            - 데이터베이스의 객체들, 즉 테이블 뷰, 인덱스 등에 대한 구조인 스키마를 정의하고 변경하며 삭제할 수 있는 기능이 있다.
            - 논리적 데이터 구조와 물리적 데이터 구조간의 사상 정의.
            - 번역한 결과가 데이터 사전에 저장된다.
            - CREATE : 스키마, 도메인, 테이블, 뷰 정의
            - ALTER : 테이블 정의 변경(필드 추가, 삭제, 갱신)
            - DROP : 스키마, 도메인, 테이블, 뷰 삭제

        2) DML(Data Manipulation Language)
            - 사용자와 데이터베이스 관리 시스템 간의 인터페이스를 정의.
            - 데이터의 검색/삽입/삭제/변경을 수행한다.
            - SELECT, INSERT, DELETE, UPDATE

        3) DCL(Data Control Language)
            - 불법적인 사용자로부터 데이터를 보호한다.
            - 무결성을 유지.
            - 데이터 회복 및 병행 제어를 수행.

    4) 튜플(Tuple)
        - 테이블의 행에 해당하며 파일 구조의 레코드와 같은 의미.

        [카디널리티] : 튜플의 수, 한 릴레이션의 튜플들의 값은 모두 상이하며, 튜플 간 순서가 없다.

    5) 속성(Attribute)
        - 테이블의 열(Column)에 해당하며 파일 구조의 항목, 필드와 같은 의미.

        [차수(Degree)] : 속성의 수, 한 릴레이션의 속성은 원자값이며 속성 간 순서가 없다.
        [도메인(Domain)] : 하나의 애트리뷰트가 가질 수 있는 원자값들의 집합.

    6) 릴레이션의 특징
        - 튜플의 유일성 : 모든 튜플은 서로 다른 값을 갖는다.
        - 튜플의 무순서성 : 하나의 릴리에션에서 튜플의 순서는 없다.
        - 속성의 원자성 : 속성값은 원자값을 갖는다.
        - 속성의 무순서성 : 각 속성은 릴레이션 내에서 유일한 이름을 가지며, 속성의 순서는 큰 의미가 없다.

    7) 슈퍼키
        - 두 개 이상의 속성으로 구성된 키 또는 혼합키를 의미.
        - 모든 튜플에 대해 유일성은 만족하지만, 최소성은 만족하지 않는다.
        - 튜플을 식별할 수 있는 모든 경우의 속성 또는 속성 집합이 슈퍼키가 될 수 있다.

    8) 후보키(Candidate Key)
        - 모든 튜플을 유일하게 식별할 수 있는 하나 또는 몇 개의 속성 집합.
        - 모든 튜플에 대해 유일성과 최소성 모두 만족.
        - 슈퍼키에서 구해진 속성, 속성 집합 중 가장 적은 속성의 집합(최소성)이 후보키가 된다.(학번,주민번호)

    9) 기본키(Primary Key)
        - 후보키 중에서 대표로 선정된 키.
        - 후보키 중 가장 적합한 속성 또는 속성 집합을 선택.

    10) 무결성
        - 릴레이션 무결성 규정은 릴레이션을 조작하는 과정에서의 의미적 관계를 명세한 것으로 정의 대상으로 도메인, 키, 종속성 등이 있다.
        
        1) 개체 무결성 
            - 기본키의 값은 널 값이나 중복 값을 가질 수 없다는 제약조건.
        
        2) 참조 무결성
            - 릴레이션 Rl에 속성 조합인 외래키를 변경하려면 이름 참조하고 있는 릴레이션 R2의 기본키도 변경해야 한다.
                이때 참조 할 수 없는 외래키 값을 가질 수 없다는 제약조건.

        3) 도메인 무결성 
            - 각 속성값은 해당 속성 도메인에 지정된 값이어야 한다는 제약조건.

    11) 데이터베이스 설계 단계
        1) 개념적 설계
            - 목표 DBMS에 독립적인 개념 스키마를 설계한다.
            - 개념 스키마 모델링과 트랜잭션 모델링을 병행 수행한다.

        2) 논리적 설계  
            - 목표 DBMS에 종속적인 논리적 스키마를 설계한다.
            - 스키마의 평가 및 정제를 한다.
            - 논리적 데이터 모델로 변환 및 트랜잭션 인터페이스를 설계한다.

        3) 물리적 설계
            - 목표 DBMS에 종속적인 물리적 구조를 설계한다.
            - 저장 레코드 양식 설계와 레코드 집중의 분석/설계, 액세스 경로 인덱싱, 클러스터링, 해싱 등의 설계가 포함.
            - 접근 경로 설계 및 트랜잭션 세부 설계를 한다.

    12) 이상 현상(Anomaly)
        - 릴레이션 조작 시 데이터들이 불필요하게 중복되어 예기치 않게 발생하는 곤란한 현상을 의미.

        1) 삽입 이상
            - 데이터를 삽입할 때 불필요한 데이터가 함께 삽입되는 현상.

        2) 삭제 이상
            - 릴레이션의 한 튜플을 삭제함으로써 연쇄 삭제로 인해 정보의 손실을 발생시키는 현상.

        3) 갱신 이상
            - 튜플 중에서 일부 속성을 갱신함으로써 벙보의 모순성이 발행하는 현상.

    13) 정규화 과정 (원부이결다조)
        비정규 릴레이션
        1NF     도메인이 원자값
        2NF     부분적 함수 종속 제거
        3NF     이행적 함수 종속 제거
        BCNF    결정자이면서 후보키가 아닌 함수 종속 제거    
        4NF     다치 종속 제거
        5NF     조인 종속성 제거

        1정규형 : 어떤 릴레이션에 속한 모든 도메인이 원자값만으로 되어 있는 릴레이션.
                  하나의 속성만 있어야 하고 반복되는 속성은 별도 테이블로 분리.
                
        2정규형 : 1정규형을 만족하고, 릴레이션에 내재된 부분 함수 종속을 제거한다.
                  기본키가 아닌 애트리뷰트 모두가 기본키에 완전 함수 종속이 되도록 부분 함수적 종속에 해당하는 속성을 별도의 테이블로 분리.

        3정규형 : 1,2 정규형을 만족하고, 속성 간 이행적 함수 종속을 제거.

        BCNF정규형 : 1,2,3정규형을 만족하고, 결정자가 후보키가 아닌 함수 종속이 제거되면 보이스/코드 정규형에 속한다.
                     후보키를 여러 개 가지고 있는 릴레이션에서 발생할 수 있는 이상 현상을 해결하기 위해 3정규형 보다 좀더 강력한 제약조건을 적용한다.
                     보이스/코드 정규형에 속하는 모든 릴레이션은 3정규형에 속하지만, 3정규형에 속하는 모든 릴레이션이 보이스/코드 정규형에 속하지는 않는다.
                     모든 결정자가 후보키.

    14) 순수 관계 연산자
        1)Select(선택)
            - 튜플 집합을 검색.
            - 릴레이션의 행에 해당하는 튜플을 선택하는 것이므로 수평적 연산이라고도 한다.
            - 기호는 σ 사용.

        2) Project(추출)
            - 속성 집합을 검색.
            - 릴레이션의 열에 해당하는 속성을 추출하는 것이므로 수직적 연산이라고도 한다.
            - 기호는 π 사용.

        3) Join(결합)
            - 두 릴레이션의 공통 속성을 연결.
            - 공통 속성을 기준으로 두 릴레이션을 합하여 새로운 릴레이션을 만드는 연산.
            - 기호는 ⋈ 사용.
        
        4) Division(나누기)
            - 기호는 ÷ 사용.

    15) 집합 연산자
        1) Union(합집합)
            - 두 릴레이션의 튜플의 합집합을 구하는 연산
            - 기호는 ∪

        2) Intersection(교집합)
            - 연관성이 있는 두 개의 릴레이션에서 중복되는 레코드를 선택하여 릴레이션을 생성
            - 기호는 ∩

        3) Difference(차집합)
            - 연관성이 있는 두 개의 릴레이션에서 중복되는 레코드를 제거하여 릴레이션을 생성
            - 기호는 -

        4) Cartesian Product(교차곱)
            - 두 릴레이션의 튜플을 교차 곱하여 생성.
            - 기호는 x

    16) 뷰 특징
        - 생성 시 CREATE문, 검색 시 SELECT문을 사용.
        - 뷰의 정의 변경 시 ALTER문을 사용할 수 없고 DROP문을 이용.
        - 뷰를 이용한 또 다른 뷰의 생성이 가능.
        - 하나의 뷰 제거 시 그 뷰를 기초로 정의된 다른 뷰도 함께 삭제.
        - 뷰에 대한 조작에서 삽입, 갱신, 삭제 연산은 제약이 따른다.
        - 뷰가 정의된 기본 테이블이 제거되면 뷰도 자동적으로 제거된다.

    17) 시스템 카탈로그
        - 시스템 자신이 필요로 하는 여러 가지 객체에 관한 정보를 포함하고 있는 시스템 데이터베이스.
        - 데이터 사전, 메타 데이터라고도 한다.
        - 시스템 카탈로그 자체도 시스템 테이블로 구성되어 있어 SQL문을 이용하여 내용 검색 가능.
        - 사용자가 직접 갱신할 수는 없으나 SQL문으로 여러 가지 객체에 변화를 주면 시스템이 재동으로 갱신됨.

    18) 트랜잭션의 특성
        1) 원자성(Atomicity)
            - 완전하게 수행이 완료되지 않으면 전혀 수행되지 않아야 한다.

        2) 일관성(Consistency)
            - 시스템의 고정 요소는 트랜잭션 수행 전후가 같아야 한다.

        3) 격리성(Isolation, 고립성)
            - 트랜잭션 실행 시 다른 트랜잭션의 간섭을 받지 않아야 한다.

        4) 영속성(Durability, 지속성)
            - 트랜잭션의 완료 결과가 데이터베이스에 영구히 기억된다.

    19) 트랜잭션의 상태
        1) 활동(Active) : 트랜잭션이 현재 실행 중인 상태를 말한다.
        2) 부분 완료(Partially Committed) : 트랜잭션이 마지막 처리를 실행한 뒤 데이터베이스에 그 처리 내용을 적용하기 직전의 상태.
        3) 완료(Committed) : 부분 완료 상태에서 정상적인 트랜잭션 처리가 이루어져 데이터베이스에 트랜잭션 처리를 적용 완료한 상태.
        4) 실패(Failed) : 트랜잭션 실행 중 오류로 인해 정상적인 처리가 되지 않아 원자성과 일관성에 문제가 발생하여 더 이상 처리가 불가능한 상태.
        5) 철회(Aborted) : 트랜잭션 처리 실패를 확인하고 처음 상태로 돌아가는 상태.

    20) 병행 제어
        - 동시에 수행되는 트랜잭션들을 일관성 있게 처리하기 위해 제어하는 것.

        [목적]
            - 데이터베이스의 공유를 최대화.
            - 데이터베이스의 일관성을 최대화.
            - 시스템 활용도 최대화.
            - 사용자에 대한 응답 시간 최소화.
        
        [병행 수행의 문제점]
            - 갱신 분실, 비완료 의존성, 모순성, 연쇄 복귀
        
        [종류] 
            - 로킹, 최적 병행 수행, 타임스탬프, 다중 버전 기법

            [타임스탬프]
                - 트랜잭션이 DMMS로부터 유일한 타임스탬프(시간 허가 인증 도장)를 부여 받는다.
                - 동시성 제어를 위한 직렬화 기법으로 트랜잭션 간의 순서를 미리 정하는 방법.

            [로킹]
                - 하나의 트랜잭션이 데이터를 액세스하는 동안 다른 트랜잭션이 그 데이터 항목을 액세스할 수 없도록 하는 병행 제어 기법.
                - 로킹 단위가 커지면 로크의 수가 적어 관리가 쉬워지지만 병행성 수준은 낮아진다.
                - 로킹 단위가 작으면 로크의 수가 많아 관리가 어려워지지만 병행성 수준은 높아진다.
                - 로킹의 대상이 되는 객체(파일,테이블,필드,레코드)의 크기를 로킹 단위라고 한다.

    21) 분산 데이터베이스 목표
        1) 위치 투명성
            - 하드웨어와 소프트웨어의 물리적 위치를 사용자가 알 필요가 없다.

        2) 중복(복제) 투명성
            - 사용자에게 통지할 필요 없이 시스템 안에 파일들과 자원들의 부가적인 복사를 자유롭게 할 수 있다.

        3) 병행 투명성
            - 다중 사용자들이 자원들을 자동으로 공유할 수 있다.

        4) 장애 투명성 
            - 사용자들은 어느 위치의 시스템에 장애가 발생했는지 알 필요가 없다.
