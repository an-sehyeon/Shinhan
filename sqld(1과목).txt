[1장 데이터 모델링의 이해]
    1. 데이터 모델의 이해
        1) 모델링의 특징
            - 추상화 : 현실 세계를 일정한 형식에 맞추어 간략하게 표현
            - 단순화 : 복잡한 현실을 기호, 문자, 그림 등으로 쉽게 이해할 수 있게 함
            - 명확화 : 애매모호함을 제거하고 명확하게 현상을 기술

        2) 데이터 모델이 제공하는 기능
            - 시스템 가시화 지원
            - 시스템 구조와 행동 명세화
            - 구조화된 틀 제공
            - 문서화
            - 다양한 관점 제공
            - 상세 수준의 구체화
        
        3) 데이터 모델링의 3단계
            (1) 개념적 데이터 모델링
                - 추상화 수준이 높고 업무 중심적, 포괄적 수준의 모델링
                - 전사적 관점에서 기업의 데이터 모델링 진행
                - 주로 ERD 산출물 생성

            (2) 논리적 데이터 모델링
                - 시스템 구축을 위한 키,속성,관계 등을 정확하게 표현
                - 재사용성이 높은 설계가 가능

            (3) 물리적 데이터 모델링
                - 실제 DB 구축을 위한 설계 단계
                - 성능,저장 등을 고려한 실제적 구현 방법 제시
                - 인덱스, 역정규화 등의 기법 사용

        4) 데이터 독립성
            (1) 외부 스키마(External Schema)
                - 사용자 관점의 스키마
                - 개인적인 데이터베이스 뷰
                - 응용 프로그램이 접근하는 영역

            (2) 개념 스키마(Conceptual Schema)
                - 통합 관점의 스키마
                - 조직 전체의 데이터베이스를 기술
                - 전체 데이터베이스의 구조 정의

            (3) 내부 스키마(Internal Schema)
                - 물리적 저장 구조
                - 실제 데이터가 저장되는 방법 정의

            (4) 독립성 종류
                - 논리적 독립성 : 개념 스키마가 변경되어도 외부 스키마에 영향 없음
                - 물리적 독립성 : 내부 스키마가 변경되어도 개념 스키마에 영향 없음

        5) ERD 표기법 종류
            - Chen 표기법 : 가장 오래된 표기법, 관계를 마름모꼴로 표시
            - IE(Information Engineering) 표기법 : 까마귀발 표기법이라고도 함, 관계를 선으로 표시
            - Barker 표기법 : 엔터티에 주식별자를 표기하지 않음, 관계는 선으로 표시

    2. 관계형 데이터베이스 개요
        1) 테이블 구조와 데이터 타입
            (1) 테이블 구성 요소
                - 컬럼(Column) : 속성, 필드
                - 행(Row) : 레코드, 튜플
                - 필드(Field) : 컬럼과 행이 만나는 지점, 실제 데이터가 저장됨

    3. 엔터티
        1) 엔터티의 분류
            (1) 유무형에 따른 분류
                - 유형 엔터티 : 물리적 형태가 있음 (예: 학생,사원,강사)
                - 개념 엔터티 : 개념적인 정보 (예: 조직,보험상품)
                - 사건 엔터티 : 업무 수행에 따른 발생 (예: 주문, 청구)
            (2) 발생시점에 따른 분류
                - 기본 엔터티 : 독립적인 생성 가능 (예: 고객,상품)
                - 중심 엔터티 : 기본 엔터티로부터 생성 (예: 계약,주문)
                - 행위 엔터티 : 두 엔터티 간의 행위로 생성 (예: 주문목록, 사원변경이력)

    4. 속성
        1) 속성의 정의
            - 업무에서 필요로 하는 최소한의 데이터 단위로, 더 이상 분리되지 않는 정보
            - 엔터티를 설명하는 요소

        2) 속성의 특성
            (1) 업무 필요성 : 해당 업무에서 필요하고 관리해야 할 정보여야 함
            (2) 함수적 종속성 : 정규화 이론에 따라 주식별자에 함수적 종속성을 가져야 함
            (3) 단일값 원칙 : 하나의 속성은 한 개의 값만을 가짐
            (4) 도메인 : 속성이 가질 수 있는 값의 범위를 정의

        3) 속성의 분류
            (1) 특성에 따른 분류
                - 기본 속성 : 업무 분석 단계에서 바로 정의되는 속성 (예: 상품이름)
                - 설계 속성 : 업무 규칙화, DB 설계 과정에서 도출되는 속성 (예: 예금분류코드)
                - 파생 속성 : 다른 속성에서 계산이나 변형으로 생성되는 속성 (예 이자)

    5. 식별자
        1) 식별자의 분류
            (1) 대표성에 따른 분류
                - 주 식별자 : 엔터티를 대표하는 식별자
                - 보조 식별자 : 대체 식별 가능한 식별자

            (2) 생성 방식에 따른 분류 
                - 내부 식별자 : 엔터티 내에서 스스로 생성되는 식별자 
                - 외부 식별자 : 다른 엔터티로부터 받아오는 식별자

            (3) 속성의 수에 따른 분류
                - 단일 식별자 : 하나의 속성으로 구성된 식별자
                - 복합 식별자 : 여러 속성의 조합으로 구성된 식별자 

            (4) 대체 가능성에 따른 분류
                - 본질 식별자 : 업무적으로 자연 발생한 식별자
                - 인조 식별자 : 시스템에서 임의로 부여한 식별자 (예: 일련번호)
                
        2) 식별자 관계와 비식별자 관계
            (1) 식별자 관계 : 부모 엔티티의 주식별자가 자식 엔터티의 주식별자에 포함되는 관계
                - 실선으로 표시
            (2) 비식별자 관계 : 부모 엔터티의 주식별자가 자식 엔터티의 일반 속성으로 포함되는 관계
                - 점선으로 표시
            (3) 관계 설정 기준
                - 자식 인스턴스가 부모 없이 독립적 존재 가능 -> 비식별자 관계
                - 자식 인스턴스의 존재가 부모에 종속적 -> 식별자 관계
                - 복합식별자가 너무 많아지면 -> 비식별자 관계 고려
                - 객체 재사용 필요시 -> 비식별자 관계 고려
                - 이력 관리 엔터티 -> 식별자 관계 고려

    6.정리 및 핵심 포인트
        1) 데이터 모델링은 현실 세계의 데이터를 추상화하여 표현하는 기법으로, 개념적/논리적/물리적 단계로 진행.
        2) 데이터 모델의 세 가지 핵심 구성요소는 엔터티(실체), 속성(특성), 관계(연관성).
        3) 관계형 데이터베이스는 SQL을 통해 데이터를 정의(DDL), 조작(DML), 제어(DCL)하며, 데이터 중복을 최소화.
        4) 엔터티는 업무에 필요한 정보 집합으로, 유형/개념/사건 엔터티로 나뉘고, 반드시 식별자와 속성을 포함해야 함.
        5) 속성은 엔터티를 설명하는 최소 데이터 단위로, 기본/설계/파생 속성 및 PK/FK/일반 속성으로 구분.
        6) 관계는 엔터티 간 연관성으로, 1:1, 1:M, N:M의 카디널리티와 필수/선택적 참여 특성을 가짐.
        7) 식별자는 인스턴스를 구분하는 속성으로, 주/보조 식별자, 내부/외부 식별자, 단일/복합 식별자 등으로 분류.
        8) 좋은 데이터 모델은 완전성, 중복 배제, 업무 규칙 반영, 데이터 재사용성, 명확한 의사소통, 통합성을 갖춰야 함.

[2장 데이터 모델과 SQL]
    1. 정규화
        1) 정규화의 정의 
            - 정규화(Normalization) : 데이터의 일관성, 최소한의 데이터 중복, 최대한의 데이터 유연성을 확보하기 위한 데이터 분해 과정
            - 엔터티를 상호 독립적인 관계로 분리하여 이상 현상(Anomaly)을 제거하는 것이 목적
            - 함수적 종속성(Functional Dependency) : 데이터 간의 종속 관계를 기반으로 정규화를 수행

        2) 이상 현상(Anomaly)
            - 삽입 이상(Insert Anomaly) : 불필요한 데이터를 함께 삽입해야만 원하는 데이터를 추가할 수 있는 현상
            - 갱신 이상(Update Anomaly) : 중복 데이터 중 일부만 수정하여 데이터 불일치가 발생하는 현상
            - 삭제 이상(Delete Anomaly) : 필요한 데이터까지 함께 삭제되는 현상

        3) 정규화 단계
            - 제1정규형 (1NF)
                ● 모든 속성의 값이 원자값(Atomic Value)이어야 함
                ● 반복 그룹이나 다중값 속성을 제거
                ● 하나의 속성에는 하나의 값만 존재해야 함

            - 제2정규형 (2NF)
                ● 1NF를 만족하면서 부분 함수 종속(Partial Dependency)을 제거
                ● 모든 비식별 속성이 주식별자 전체에 완전 함수 종속이어야 함
                ● 복합 식별자의 일부에만 종속되는 속성을 분리

            - 제3규형 (3NF)
                ● 2NF를 만족하면서 이행 함수 종속(Transitive Dependency)을 제거
                ● 비식별 속성 간의 종속 관계를 제거
                ● A -> B -> C에서 A -> C의 간접 종속이 존재하면 분리

            - BCNF (Boyce-Codd Normal Form)
                ● 3NF를 만족하면서 결정자(Determinant)가 모두 후보키어야 함
                ● 후보키가 아닌 속성이 결정자인 경우를 제거
                ● 모든 결정자가 후보키인 상태

            - 제4규형 (4NF)
                ● 다치 종속(Multi-Valued Dependency)을 제거
                ● 하나의 속성이 여러 개의 독립적인 다중값과 관련되는 경우를 분리

            - 제5규형 (5NF)
                ● 조인 종속(Join Dependency)을 제거
                ● 분해된 테이블을 다시 조인했을 때 원래의 테이블과 동일해야 함.

            * 원부이결다조

        4) 정규화의 성능
            - 정규화는 조회 성능을 저하시킬 수도, 향상시킬 수도 있음
            - 정규화를 하면 조인이 증가하여 조회 성능이 떨어질 수 있음
            - 반면, 중복이 제거되어 데이터 일관성 유지 -> 특정 조회 성능 향상
            - 입력/수정/삭제 성능은 일반적으로 향상됨 (중복 데이터 감소로 처리량 감소)

    2. 반정규화
        1) 반정규화의 정의
            - 반정규화(Denormalization) : 정규화된 엔터티, 속성, 관계에 대해 성능 향상과 개발 운영의 단순화를 위해 중복, 통합, 분리 등을 수행하는 데이터 모델링 기법
            - 데이터 무결성이 깨질 수 있는 위험성이 있으므로 신중한 판단 필요

        2) 반정규화 적용 시 고려사항
            - 뷰(View) 활용으로 해결 가능한지 검토
            - 인덱스 조정으로 해결 가능한지 검토
            - 클러스터링 적용으로 해결 가능한지 검토
            - 파티셔닝이나 캐시 적용 등 다른 방안 검토
            * 위 방안으로도 해결되지 않을 때 반정규화를 적용

        3) 반정규화 기법
            (1) 테이블 반정규화
                - 테이블 병합 : 1:1 관계 또는 1:M 관계의 테이블을 하나로 합침
                - 테이블 분할
                    ● 수직 분할 : 컬럼 단위로 테이블을 나눔 (자주 사용하는 컬럼과 그렇지 않은 컬럼을 분리)
                    ● 수평 분할 : 행 단위로 테이블을 나눔 (지역별, 기간별 등으로 분리)
                - 테이블 추가
                    ● 중복 테이블 추가 : 다른 업무이거나 서버가 다른 경우 중복 테이블 생성
                    ● 통계 테이블 추가 : 통계 데이터를 미리 계산하여 별도 테이블에 저장
                    ● 이력 테이블 추가 : 변경 이력을 관리하기 위한 테이블 추가
                    ● 부분 테이블 추가 : 자주 사용하는 컬럼만 모아 별도 테이블 생성

            (2) 컬럼 반정규화
                - 중복 컬럼 추가 : 조인 감소를 위해 다른 테이블의 컬럼을 중복 저장
                - 파생 컬럼 추가 : 계산값을 미리 저장하여 조회 성능 향상 (예: 합계, 평균)
                - 이력 테이블 컬럼 추가 : 최신 데이터를 빠르게 조회하기 위한 컬럼 추가
                - PK에 의한 컬럼 추가 : PK에 포함된 정보를 별도 컬럼으로 저장하여 인덱스 접근 편의 제공
                - 응용시스템 오동작을 위한 컬럼 추가 : 이전 데이터와의 비교를 위한 컬럼

            (3) 관계 반정규화
                - 중복 관계 추가 : 조인 경로를 단축시키기 위해 이미 존재하는 관계를 중복으로 추가

    3. 트랜잭션
        1) 트랜잭션의 정의
            - 트랜잭션(Transaction) : 데이터베이스의 상태를 변환시키는 하나의 논리적 작업 단위
            - 하나의 업무 단위로 묶여 있어, 전체가 수행되거나 전체가 취소되어야 함.

        2) 트랜잭션의 특성
            (1) 원자성(Atomicity)
                - 트랜잭션의 연산은 전부 실행되거나 전부 취소되어야 함
                - 일부만 수행되어서는 안됨

            (2) 일관성(Consistency)
                - 트랜잭션 수행 전후로 데이터베이스의 상태가 일관되어야 함
                - 데이터 무결성 제약 조건을 항상 만족

            (3) 고립성(Isolation)
                - 하나의 트랜잭션이 실행 중일 때 다른 트랜잭션이 접근할 수 없음
                - 각 트랜잭션은 독립적으로 수행

            (4) 영속성(Durability)
                - 트랜잭션이 성공적으로 완료되면 그 결과는 영구적으로 반영
                - 시스템 장애가 발생하더라도 결과는 보존

        3) 트랜잭션과 데이터 모델링
            - 하나의 트랜잭션에 관련된 데이터는 가능하면 하나의 엔터티에 배치
            - 트랜잭션의 단위가 데이터 모델의 엔터티 도출에 영향을 줌

    4. NULL
        1) NULL의 특성
            (1) 산술 연산
                - NULL이 포함된 산술 연산의 결과는 항상 NULL
            (2) 비교 연산
                - NULL과의 비교 결과는 항상 Unknown(알 수 없음)
            (3) 논리 연산
                - NULL은 3가지 값 논리에 따름
                    ● TRUE AND Unknown = Unknown
                    ● FALSE AND Unknown = FALSE
                    ● TREU OR Unknown = TRUE
                    ● FALSE OR Unknown = Unknown
                    ● NOT Unknown = Unknown

        2) NULL 관련 함수
            (1) NVL(Oracle) / ISNULL(SQL Server)
                - NULL을 지정한 값으로 치환
                - NVL(컬럼,대체값) : 컬럼이 NULL이면 대체값 반환
            (2) NULLIF 
                - 두 값이 같으면 NULL 반환, 다르면 첫 번째 값 반환
                - NULL(값1,값2) : 값1 = 값2이면 NULL, 아니면 값1

            (3) COALESCE 
                - 인수 중 첫 번째로 NULL이 아닌 값을 반환
                - COALESCE(값1,갑2,값3,....) : 왼쪽부터 순서대로 NULL이 아닌 첫 번째 값 반환

        3) 집계 함수와 NULL
            - SUM,AVG,COUNT(컬럼),MAX,MIN : NULL 값을 제외하고 연산
            - COUNT(*) : NULL 포함 전체 행 수를 카운트
            - AVG 주의 : NULL을 제외한 행의 평균이므로, 전체 행의 평균과 다를 수 있음

    5. 본질식별자 vs 인조식별자
        1) 본질식별자
            - 본질식별자(Natural Identifier) : 업무에 의해 자연적으로 만들어진 식별자
            - 업무적 의미를 가지고 있어 데이터의 의미를 직관적으로 파악 가능
            - 예 : 주민등록번호, 사업자등록번호, 수강신청(학번+과목번호)        

        2) 인조식별자
            - 인조식별자(Surrogate Identifier) : 인위적으로 부여한 식별자
            - 업무적 의미는 없으나 시스템 관리를 위해 생성
            - 주로 자동 증가(Auto Increment) 번호나 시퀀스를 사용
            - 예 : 수강신청번호(시퀀스), 주문번호(자동채번)

        3) 인조식별자 사용 시 고려사항
            - 불필요한 인조식별자 남용 주의                             [일짝]
                ● 본질 식별자만으로 충분한 경우 인조식별자 추가 지양
            - 중복 데이터 발생 위험 
                ● 인조식별자만으로는 업무적 중복을 방지하기 어려움
                ● 예 : 수강신청번호만 PK로 설정 시, 동일 학생이 같은 과목을 중복 신청 가능
                ● 본질 식별자를 유니크 제약조건으로 설정하거나 PK에 포함 필요
            - 불필요한 인덱스 증가
                ● 인조식별자를 추가하면 관련 인덱스도 추가 필요
            - 인조식별자가 적합한 경우
                ● 본질식별자가 너무 많은 컬럼으로 구성된 복합식별자일 때
                ● 자식 엔터티로 식별자가 계속 전이 되어 관리가 복잡한 경우
                ● 본질식별자의 값이 너무 길어 인덱스 성능에 영향을 줄 때

    6. 계층형 데이터 모델
        1) 계층형 데이터 모델의 정의
            - 엔터티 내에서 자기 자신과의 관계(Self-Relationship)를 가지는 데이터 모델
            - 조직도,카테고리,메뉴 구조 등 트리 구조의 데이터를 표현
            - 하나의 테이블 내에서 상위-하위 관계를 부모키(FK)로 표현

        2) 셀프 조인(Self-Join)
            - 같은 테이블을 두 번 이상 참조하여 조인하는 방식
            - 계층형 데이터에서 상위-하위 관계를 조회할 때 사용
            - 테이블에 별칭을 부여하여 마치 다른 테이블처럼 사용
            - 예: 사원 테이블에서 사원과 해당 사원의 관리자 정보를 함께 조회

        3) 계층형 SQL
            (1) Oracle의 계층형 쿼리
                - START WITH : 계층의 시작점(루트) 지정
                - CONNECT BY PRIOR : 부모-자식 관계의 방향 지정
                - LEVEL : 현재 계층의 깊이(레벨) 반환
                - ORDER SIVLINGS BY : 같은 레벨 내에서 정렬

            (2) SQL Server의 계층형 쿼리
                - CTE(Common Table Expression)와 재귀 쿼리를 사용하여 구현
                - WITE RECURSIVE 구문 활용

        4) 계층형 데이터 모델 설계 시 고려사항
            - 순환 참조(Cycle)가 발생하지 않도록 주의
            - 루트 노드의 부모키는 NULL로 설정
            - 계층의 깊이가 깊어지면 조회 성능 저하 가능
            - 필요 시 경로(PATH) 컬럼을 추가하여 탐색 성능 향상

        5) 정리 및 핵심 포인트
            (1) 정규화는 데이터 중복을 제거하고 이상 현상을 방지하기 위해 테이블을 분해하는 과정이며, 1NF(원자값) -> 2NF(부분종속 제거) -> 3NF(이행종속 제거) -> BCNF(결정자=후보키) 순으로 진행.
            (2) 반정규화는 성능 향상을 위해 정규화된 모델에 중복/통합/분리를 적용하는 기법이며, 반드시 다른 대안(뷰,인덱스,파티셔닝 등)을 먼저 검토한 후 적용.
            (3) 트랜잭션은 ACID(원자성,일관성,고립성,영속성) 특성을 가지며, 전부 수행되거나 전부 취소되는 논리적 작업 단위.
            (4) NULL은 '값이 없음'을 의미하며, 산술 연산 결과는 NULL, 비교 연산 결과는 Unknown이 됨. NVL,NULLIF,COALESCE등의 함수로 처리.
            (5) 집계 함수(SUM, AVG, MAX, MIN, COUNT(컬럼)는 NULL을 제외하고 연산하며, COUNT(*)만 NULL을 포함하여 전체 행 수를 계산.
            (6) 본질식별자는 업무적으로 자연 발생한 식별자이고, 인조식별자는 시스템 편의를 위해 인위적으로 부여한 식별자. 인조식별자 남용 시 중복 데이터 발생 위험이 있다.
            (7) 계층형 데이터 모델은 자기 자신과의 관계를 가지며, 셀프 조인이나 계층형 쿼리(START WITE/CONNECT BY,CTE)를 통해 조회.
            (8) 정규화는 입력/수정/삭제 성능을 향상시키고, 반정규화는 조회 성능을 향상시키는 대신 데이터 무결성 위험이 있으므로 균형 있는 적용이 중요.

    1) SELECT 문 작성 순서
        SELECT -> FROM -> WHERE -> GROUP BY -> HAVING -> ORDER BY
    2) 컴퓨터가 해석하는 순서
        FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY
        (FWGHSO)
    3) SELECT 문 주요 요소
        - DISTINCT는 중복 제거

5. 별칭(alias) 사용법과 주의점
    - 별칭은 AS 키워드를 사용하지만 생략 가능.
    - 별칭 명명 규칙
        1. 숫자 및 특수문자 사용 금지(단, 쌍따옴표로 감싸면 가능)
        2. 예약어(예 : select, from 등) 사용 금지
    - where 절은 select 절보다 먼저 실행되므로, where에서 컬럼 별칭 사용 불가

6. 문자열 연결과 함수

      문자 함수             예 : SUBSTR, TRIM                         SUBSTR('David',1,2) = 'Da'
