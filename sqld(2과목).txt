[1장 SQL 기본]
    1. SELECT 문
        1) DISTINCT 
            - 중복된 데이터가 있을 때 1건으로 처리하여 출력

    2. 함수
        1) SQL 내장 함수 개요
            (1) 단일행 함수
                - 각 행에 대해 하나의 결과값을 반환
                - 문자형, 숫자형, 날짜형, 변환형 함수 등
            (2) 다중행 함수
                - 여러 행의 데이터를 집계하여 하나의 결과값을 반환
                - 집계 함수, 그룹 함수, 윈도우 함수 등

        2) 문자형 함수
            (1) LOWER : 문자열을 소문자로 변환
                - SELECT LOWER('HELLO WORLD') -> 'hello world'
            (2) UPPER : 문자열을 대문자로 변환
                - SELECT UPPER('hello world') -> 'HELLO WORLD'
            (3) SUBSTR : 문자열의 일부분을 추출 
                - SELECT SUBSTR('Hello World', 1, 5) -> 'Hello'
            (4) LENGTH : 문자열의 길이를 반환
                - SELECT LENGTH('Hello World') -> 11
            (5) TRIM : 문자열의 양쪽 공백을 제거
            (6) LTRIM : 문자열의 왼쪽 공백을 제거
            (7) RTRIM : 문자열의 오른쪽 공백을 제거
            (8) CONCAT : 두 문자열을 연결

        3) 숫자형 함수
            (1) ABS : 숫자의 절댓값을 반환
            (2) SIGN : 숫자의 부호를 반환
            (3) ROUND : 숫자를 반올림
            (4) TRUNC : 숫자를 절삭
                - SELECT TRUNC(3.14159, 2) -> 3.14
            (5) CEIL : 숫자보다 크거나 같은 최소 정수
                - SELECT CEIL(4.3) -> 5
            (6) FLOOR : 숫자보다 작거나 같은 최대 정수
                - SELECT FLOOR(4.7) -> 4
            (7) MOD : 나눗셈 후 나머지 
                - SELECT MOD(17, 5) -> 2
            (8) POWER : 거듭제곱
                - SELECT POWER(2, 3) -> 8
            (9) SQRT : 제곱근 
                - SELECT SQRT(9) -> 3

        4) 날짜형 함수
            (1) SYSDATE : 현재 날짜와 시각 반환
            (2) ADD_MONTHS : 지정한 개월 수 만큼 날짜를 더함
            (3) MONTHS_BETWEEN : 두 날짜 사이의 개월 수를 계산
                - SELECT MONTHS_BETWEEN(SYSDATE, '2024-01-01')
            (4) NEXT_DAY : 지정한 날짜 이후의 특정 요일 날짜
                - SELECT NEXT_DAY('2024-07-20', '월요일')
            (5) LAST_DAY : 해당 월의 마지막 날짜
            (6) EXTRACT : 날짜에서 특정 부분 추출

        5) 변환형 함수
            (1) TO_CHAR : 날짜/숫자를 문자열로 변환
                - SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD')
            (2) TO_DATE : 문자열을 날짜로 변환
                - SELECT TO_DATE('2024-07-01','YYYY-MM-DD')
            (3) TO_NUMBER : 문자열을 숫자로 반환
            (4) CAST : 데이터 타입 변환
                - SELECT CAST('12345', AS NUMBER)

        6) NULL 관련 함수
            (1) NVL(오라클) : NULL인 경우 지정한 값으로 대체
            (2) COALESCE : 최초의 NULL이 아닌 값 반환
            (3) NULLIF : 두 값이 같으면 NULL, 다르면 첫 번째 값

    3. GROUP BY 절, HAVING 절, ORDER BY 절
        1) GROUP BY 절
            - GROUP BY 절에서는 별칭 사용 불가
            - SELECT 절에 GROUPY BY 절에 없는 칼럼은 사용 불가

        2) HAVING 절
            - WHERE절과 HAVING절의 차이
                ● WHERE : 그룹화 전 개별 행을 필터링(집계 함수 사용 불가)
                ● HAVING : 그룹화 후 그룹을 필터링(집계 함수 사용 가능)

        * SQL 실행 순서
            - F > W > G > H > S > O

    4. JOIN
        1) JOIN의 종류
            (1) INNER JOIN
                - 두 테이블에서 공통된 값을 가진 행만 반환
                SELECT E.EMPNO, E.ENAME, D.DNAME
                FROM EMP E INNER JOIN DEPT D
                ON E.DEPTNO = D.DEPTNO;

            (2) LEFT OUTER JOIN
                - 왼쪽 테이블의 모든 행과 오른쪽 테이블의 일치하는 행을 반환.
                - 일치하는 행이 없으면 NULL로 표시
                SELECT E.EMPNO, E.ENAME, D.DNAME
                FROM EMP E LEFT OUTER JOIN DEPT D
                ON E.DEPTNO = D.DEPTNO;

                - 오라클 문법
                SELECT E.EMPNO, E.ENAME, D.DNAME
                FROM EMP E, DEPT D
                WHERE E.DEPTNO = D.DEPTNO(+);

            (3) RIGHT OUTER JOIN
                - 오른쪽 테이블의 모든 행과 왼쪽 테이블의 일치하는 행을 반환
                SELECT E.EMPNO, E.ENAME, D.DNAME
                FROM EMP E RIGHT OUTER JOIN DEPT D
                ON E.DEPTNO = D.DEPTNO;

            (4) FULL OUTER JOIN
                - 양쪽 테이블의 모든 행을 반환
                - 일치하지 않는 행은 NULL로 표시
                SELECT E.EMPNO, E.ENAME, D.DNAME
                FROM EMP E FULL OUTER JOIN DEPT D
                ON E.DEPTNO = D.DEPTNO;

            (5) CROSS JOIN
                - 두 테이블 간의 모든 행을 조합.(카티시안 곱)
                SELECT E.ENAME, D.DNAME
                FROM EMP E CROSS JOIN DEPT D;

        2) 등가 JOIN과 비등가 JOIN
            (1) 등가 JOIN(EQUI JOIN)
                - =연산자를 사용하여 두 테이블의 칼럼이 같은 값인 경우를 조인
                SELECT E.ENAME, D.DNAME
                FROM EMP E JOIN DEPT D
                ON E.DEPTNO = D.DEPTNO;

            (2) 비등가 JOIN(NON-EQUI JOIN)
                - =외의 연산자(>,<,BETWEEN 등)를 사용하여 조인
                SELECT E.ENAME, E.SAL, S.GRADE
                FROM EMP E JOIN SALGRADE S
                ON E.SAL BETWEEN S.LOSAL AND S.GISAL;

        3) NATURAL JOIN과 USING 조건절
            (1) NATURAL JOIN
                - 두 테이블에 동일한 이름을 가진 모든 칼럼에 대해 자동으로 조인
                SELECT ENAME, DNAME
                FROM EMP NATURAL JOIN DEPT;

            (2) USING 조건절
                - 조인할 특정 칼럼을 명시
                - 동일한 이름의 칼럼이 하나 이상 있을 때 유용
                SELECT ENAME, DNAME, DEPTNO
                FROM EMP JOIN DEPT USING (DEPTNO);

        4) 3개 이상 테이블 JOIN
            SELECT E.ENAME, D.DNAME, L.CITY
            FROM EMP E
            JOIN DEPT D ON E.DEPTNO = D.DEPTNO
            JOIN LOCATIONS L ON D.LOC_ID = L.LOC_ID;

        5) 정리 및 핵심 포인트
            1. SELECT문은 FROM > WHERE > GROUP BY > HAVING > SELECT > ORDER BY 순서로 실행
            2. 함수는 단일행/다중행으로 구분된다. 단일행 함수는 각 행별 결과, 집계 함수는 그룹 전체 결과를 반환.
            3. WHERE절은 그룹화 이전 필터, HAVING 절은 그룹화 이후 필터. 집계함수를 쓰려면 HAVING을 사용.
            4. INNER JOIN은 교집합, OUTER JOIN은 포함 관계를 유지하며 NULL로 채운다. 조인 조건에 인덱스가 잡히도록 설계하면 성능을 크게 개선할 수 있음.
            5. 동적 쿼리를 자주 작성한다면 WHERE 1=1 패턴으로 조건을 손쉽게 추가/제거하고, 별칭/CASE/서브쿼리를 적절히 사용해 가독성과 재사용성을 높인다.
            6. SQL은 단순 질의어를 넘어 데이터 통합/보고/품질 관리 등 거의 모든 데이터 작업의 공통 언어.

[2장 SQL 활용]
    1. 서브쿼리
        1) 서브쿼리 사용 시점
            - 복잡한 조건 필터링
            - 계산된 칼럼 생성
            - 임시 테이블(INLINE-VIEW) 활용
            - 조인보다 간단한 존재 여부 판정(예: EXISTS, IN)

        2) 서브쿼리 종류
            (1) 동작 방식에 따른 분류
                1) 연관 서브쿼리(Correlated Subquery)
                    - 메인 쿼리의 각 행과 관련되어 처리
                    - 메인 쿼리 한 행을 읽을 때마다 서브쿼리가 실행됨
                    SELECT ENAME, DEPTNO, SAL
                    FROM EMP E1
                    WHERE SAL > (SELECT AVG(SAL)
                                FROM EMP E2
                                WHERE E1.DEPTNO = E2.DEPTNO);

                2) 비연관 서브쿼리(Un-Correlated Subquery)
                    - 메인 쿼리와 독립적으로 실행
                    - 한 번만 실행되어 결과를 메인 쿼리에 전달
                    SELECT ENMAE, SAL
                    FROM EMP
                    WHERE SAL > (SELECT AVG(SAL) FROM EMP);

            (2) 반환 형태에 따른 분류
                1) 단일행 서브쿼리(Single Row Subquer)
                    - 하나의 행만 반환
                    - 단일행 비교 연산자(=,>,<,>=,<=,<>) 사용
                    SELECT ENAME, SAL
                    FROM EMP
                    WHERE SAL > (SELECT AVG(SAL) FROM EMP);

                2) 다중행 서브쿼리(Multiple Row Subquery)
                    - 여러 행을 반환
                    - 다중행 비교 연산자(IN,ANY,ALL,EXISTS) 사용
                    SELECT ENMAE, SAL
                    FROM EMP
                    WHERE DEPTNO IN (SELECT DEPTNO FROM DEPT WHERE LOC = 'NEW YORK');

                3) 다중칼럼 서브쿼리 (Multiple Column Subquery)
                    - 여러 칼럼을 반환
                    - 복합 조건 비교에 사용
                    SELECT * 
                    FROM EMP 
                    WHERE (JOB, DEPTNO) IN (SELECT JOB, DEPTNO FROM EMP WHERE ENAME = 'SMITH');

        3) 서브쿼리 활용법
            (1) WHERE 절에서의 서브쿼리  
            SELECT ENAME, SAL
            FROM EMP 
            WHERE SAL > (SELECT AVG(SAL) FROM EMP)
            ORDER BY SAL DESC;

            (2) HAVING 절에서의 서브쿼리
            SELECT DEPTNO, AVG(SAL)
            FROM EMP 
            GROUP BY DEPTNO 
            HAVING AVG(SAL) > (SELECT AVG(SAL) FROM EMP);

            (3) SELECT 절에서의 서브쿼리
            SELECT ENAME, SAL, 
                            (SELECT AVG(SAL) FROM EMP) AS AVG_SAL
            FROM EMP
            ORDER BY SAL DESC;

            (4) FROM 절에서의 서브쿼리(인라인 뷰)
            SELECT E.ENAME, E.SAL, A.AVG_SAL
            FROM EMP E,
                    (SELECT AVG(SAL) AS AVG_SAL FROM EMP) A
            WHERE E.SAL > A.AVG_SAL
            ORDER BY SAL DESC;

        4) DML에서의 서브쿼리 활용
            (1) INSERT와 서브쿼리
            INSERT INTO EMP (EMPNO, ENAME, SAL)
            VALUSE((SELECT MAX(EMPNO) + 1 FROM EMP), 'NEW_EMP', 3000);

            (2) UPDATE와 서브쿼리
            UPDATE EMP 
            SET SAL = SAL * 1.1
            WHERE DEPTNO = (SELECT DEPTNO FROM DEPT WHERE DNAME = 'SALES');

            (3) DELETE와 서브쿼리 
            DELETE FROM EMP
            WHERE SAL < (SELECT AVG(SAL) FROM EMP);

    2. 뷰(VIEW)의 개념과 활용법
        - 뷰는 하나 이상의 테이블에 있는 데이터의 부분집합을 논리적으로 표현한 가상 테이블.
        - 실제 데이터를 가지고 있지 않고, 데이터를 추출하는 SQL문을 저장하고 있다.

        1) 뷰의 장점
            - 복잡한 쿼리 단순화
            - 데이터 보안 강화(필요한 칼럼만 제공)
            - 데이터 독립성 확보
            - 동일 데이터에 대한 다양한 관점 제공

        2) 뷰의 생성과 활용
            CREATE VIEW EMP_DEPT_V AS
            SELECT E.EMPNO, E.ENAME, D.DNAME, E.SAL
            FROM EMP E, DEPT D
            WHERE E.DEPTNO = D.DEPTNO;

            - 뷰 사용
            SELECT * FROM EMP_DEPT_V WHERE SAL > 2000;

    3. 집합 연산자
        - 두 개 이상의 SELECT문의 결과를 하나의 결과로 집합하는 연산자.
        
        1) 집합 연산자 종류
            (1) UNION(합집합, 중복 제거)
                - 두 개의 SELECT문 결과를 하나로 합치고, 중복된 행은 제거.
                SELECT DEPTNO, DNAME FROM DEPT
                UNION
                SELECT DEPTNO, JOB FROM EMP;

            (2) UNION ALL(합집합, 중복 포함)
                - 두 개의 SELECT문 결과를 하나로 합치고, 중복된 행도 그대로 포함.
                SELECT DEPTNO FROM DEPT
                UNION ALL
                SELECT DEPTNO FROM EMP;

            (3) INTERSECT(교집합)
                - 두 SELECT문의 결과에 모두 포함된 행만 반환
                SELECT DEPTNO FROM DEPT
                INTERSECT
                SELECT DEPTNO FROM EMP;

            (4) MINUS / EXCEPT (차집합)
                - 첫 번째 SELECT문의 결과에서 두 번째 SELECT문의 결과에 포함된 행을 제외한 나머지를 반환
                 (ORACLE은 MINUS, SQL SERVER는 EXCEPT 사용)
                 SELECT DEPT FROM DEPT 
                 MINUS 
                 SELECT DEPTNO FROM EMP;

        2) 집합 연산자 사용 조건
            - 각 SELECT문의 칼럼 수가 동일해야 함.
            - 대응되는 칼럼의 데이터 타입이 같거나 호환 가능해야 함.
            - 결과는 첫 번째 SELECT문의 칼럼 이름을 따른다.
            - ORDER BY절은 전체 결과에 대헤 마지막에 한 번만 사용함.

    4. 그룹 함수
        1) 다차원 집계
            (1) ROLLUP
                - ROLLUP은 GROUP BY절과 함께 사용하여 지정된 칼럼의 소계와 총계를 자동으로 산출. 계층적 구조로 집계를 생성.
                SELECT DEPTNO, JOB, SUM(SAL) AS TOTAL_SALARY
                FROM EMP
                GROUP BY ROLLUP(DEPTNO, JOB)
                ORDER BY DEPTNO;

                - 이 쿼리는 다음 그룹별 총합을 계산함.
                    - 각 부서와 직무 조합
                    - 각 부서별
                    - 전체 총합

            (2) CUBE
                - 지정된 칼럼들의 가능한 모든 조합에 대해 집계를 수행
                SELECT DEPTNO, JOB, SUM(SAL)
                FROM EMP 
                GROUP BY CUBE(DEPTNO, JOB);
                 
                - 이 쿼리는 다음  그룹별 총합을 계산함.
                    - 각 부서와 직무 조합 
                    - 각 부서별 
                    - 각 직무별 
                    - 전체 총합

            (3) GROUPING SETS
                - 원하는 특정 그룹의 집계만 수행할 수 있도록 해줌.
                - ROLLUP이나 CUBE의 일부 기능만 필요할 때 유용.
                SELECT DEPTNO, JOB, SUM(SAL)
                FROM EMP 
                GROUP BY GROUPING SETS((DEPTNO, JOB), (DEPTNO), (JOB), ());

        2) GROUPING/CASE/DECODE 활용
            (1) GROUPING 함수
                - 특정 칼럼이 집계에 사용되었는지 여부를 반환
                - 집계에 사용되었으면 0, 그렇지 않으면 1을 반환
                SELECT 
                    CASE GROUPING(DEPTNO) WHEN 1 THEN '전체 부서' ELSE TO_CHAR(DEPTNO) END AS DEPTNO,
                    CASE GROUPING(JOB) WHEN 1 THEN '전체 직무' ELSE JOB END AS JOB,
                    SUM(SAL) AS TOTAL_SALARY
                FROM EMP 
                GROUP BY ROLLUP(DEPTNO, JOB);

            (2) CASE와 DECODE 활용
                - CASE 표현식이나 DECODE 함수를 사용하여 집계 결과의 가독성을 높일 수 있다.

                [ ORACLE DECODE 예시 ]
                SELECT  
                    DECODE(GROUPING(DEPTNO), 1, '전체 부서', TO_CAHR(DEPTNO)) AS DEPTNO,
                    DECODE(GROUPING(JOB), 1, '전체 직무', JOB) AS JOB,
                    SUM(SAL) AS TOTAL_SALARY
                FROM EMP
                GROUP BY ROLLUP(DEPTNO, JOB);

                [ CASE 문 예시 ]
                SELECT  
                    CASE
                        WHEN GROUPING(DEPTNO) = 1 THEN '전체 부서'
                        ELSE TO_CAHR(DEPTNO)
                    END AS DEPTNO,
                    CASE
                        WHEN GROUPING(JOB) = 1 THEN '전체 직무'
                        ELSE JOB 
                    END AS JOB,
                    SUM(SAL) AS TOTAL_SALARY
                FROM EMP
                GROUP BY ROLLUP(DEPTNO, JOB);

    5. 윈도우 함수
        - 행과 행 간의 관계를 쉽게 정의하기 위해 제공되는 합수.
        - 특정 윈도우(파티션)에 대해 계산을 수행.
        - 집계 함수와 달리 행이 그대로 유지되면서 값이 추가됨.

        1) 윈도우 함수 기본 구문
            윈도우함수(인자) OVER(
                [PARTITION BY 칼럼]
                [ORDER BY 칼럼]
                [ROWS | RANGE BETWEEN 시작점 AND 끝점]
            )    

            - PARTITION BY : 계산을 적용할 행 그룹 지정
            - ORDER BY : 파티션 내에서 행 순서 지정
            - ROWS | RANGE : 프레임 지정(현재 행을 기준으로 계산할 범위)

        2) 윈도우 함수 종류
            [순위 관련 함수]
            (1) ROW_NUMBER()
                - 파티션 내에서 순차적인 번호 부여(중복 값에도 순차적인 번호)
                SELECT ENAME, SAL, 
                            ROW_NUMBER() OVER(ORDER BY SAL DESC) AS RN 
                FROM EMP;

            (2) RAND()
                - 파티션 내에서 순위를 매기되, 동일한 값은 동일한 순위(다음 순위는 건너뜀)
                SELECT ENAME, SAL,
                            RANK() OVER(ORDER BY SAL DESC) AS RANK_SAL
                FROM EMP;

            (3) DENSE_RANK()
                - RANK와 유사하나, 동일한 순위 다음에 순차적인 값을 부여(건너뛰지 않음)
                SELECT ENAME, SAL,
                            DENSE_RANK() OVER(ORDER BY SAL DESC) AS DENSE_RANK_SAL
                FROM EMP;

            [집계 관련 함수]
            (1) SUM() OVER  
                - 파티션별 합계 계산
                SELECT ENAME, DEPTNO, SAL,
                                SUM(SAL) OVER(PARTITION BY DEPTNO) AS DEPT_SUM
                FROM EMP;

            (2) AVG() OVER
                - 파티션별 평균 계산
                SELECT ENAME, DEPTNO, SAL,
                                AVG(SAL) OVER(PARTITION BY DEPTNO) AS DEPT_AVG
                FROM EMP;

            (3) MAX() OVER, MIN() OVER
                - 파티션별 최댓값, 최솟값 계산
                SELECT ENAME, DEPTNO, SAL,
                            MAX(SAL) OVER(PARTITION BY DEPTNO) AS DEPT_MAX,
                            MIN(SAL) OVER(PARTITION BY DEPTNO) AS DEPT_MIN
                FROM EMP;

            [행 이동 관련 함수]
            (1) LAG()
                - 이전 행의 값을 참조
                SELECT ENAME, HIREDATE, SAL,
                            LAG(SAL) OVER(ORDER BY HIREDATE) AS PREV_SAL
                FROM EMP;

            (2) LEAD()
                - 다음 행의 값을 참조
                SELECT ENAME, HIREDATE, SAL,
                            LEAD(SAL) OVER(ORDER BY HIREDATE) AS NEXT_SAL
                FROM EMP;

            [누적 관련 함수]
            (1) CUME_DIST()
                - 누적 분포 값을 계산(현재 행보다 작거나 같은 값의 누적 개수 / 전체 행 수)
                SELECT ENAME, SAL,
                            CUME_DIST() OVER(ORDER BY SAL) AS CUM_DIST 
                FROM EMP;

            (2) PERCENT_RANK()
                - 백분위 순위 계산((현재 행 순위 -1) / (전체 행 수 -1))                                
                SELECT ENAME, SAL,
                            PERCENT_RANK() OVER(ORDER BY SAL) AS PERCENT_RANK
                FROM EMP;

    6. Top N 쿼리
        1) ROWNUM 슈도 칼럼
            - ORACLE에서 제공하는 가상 칼럼으로 쿼리 결과의 각 행에 1부터 시작하는 순차적인 번호를 부여.
            SELECT ROWNUM, ENAME, SAL
            FROM EMP
            WHERE ROWNUM <= 5;

        2) Top N 쿼리 활용법
            [ORACLE에서의 Top N 쿼리(ROWNUM 활용)]            
            - 잘못된 방법 (원하는 결과가 나오지 않음)
            SELECT ROWNUM, ENAME, SAL
            FROM EMP
            WHERE ROWNUM <= 5
            ORDER BY SAL DESC;

            - 올바른 방법 (인라인 뷰 활용)
            SELECT ROWNUM, E.*
            FROM (SELECT ENAME, SAL
                  FROM EMP
                  ORDER BY SAL DESC) E
            WHERE ROWNUM <= 5;

            [SQL Server에서의 Top N 쿼리]
            SELECT TOP 5 ENAME, SAL
            FROM EMP
            ORDER BY SAL DESC;

            [표준 SQL의 FETCH절 사용]
            SELECT ENAME, SAL
            FROM EMP
            ORDER BY SAL DESC
            FETCH FIRST 5 ROWS ONLY;

            [페이징 처리]
            - 11~20번째 행 조회
            SELECT *
            FROM (
                SELECT ROWNUM AS RN, E.*
                FROM (SELECT * FROM EMP ORDER BY SAL DESC) E
                WHERE ROWNUM <= 20
                )
            WHERE RN >= 11;

    7. 셀프 조인과 계층형 질의
        1) 계층형 질의 개념 및 문법
            - 테이블에 저장된 계층적 구조의 데이터를 조회하는 방법.
            - ORACLE에서는 START WITH와 CONNECT BY절을 사용.
            SELECT [칼럼 목록], LEVEL
            FROM [테이블명]
            START WITH [최상위 조건]
            CONNECT BY [PRIOR 부모키 = 자식키 | 자식키 = PRIOR 부모키];

        2) 계층형 질의 주요 요소
            - START WITH : 계층 구조의 시작점(루트 노드) 지점
            - CONNECT BY : 부모-자식 관계를 정의
            - LEVEL : 계층의 깊이를 나타내는 의사 칼럼
            - CONNECT_BY_ROOT : 현재 행의 최상위 조상 노드를 반환
            - SYS_CONNECT_BY_PATH : 루트부터 현재 노트까지의 경로를 문자열로 반환
            - CONNECT_BY_ISLEAF : 현재 행이 리프 노드인지 여부

        3) 계층형 질의 예제
            - 조직도 조회(최상위 관리자부터)
            SELECT ENAME, EMPNO, MGR, LEVEL,
                        LPAD(' ', (LEVEL-1) *2) || ENAME AS ORG_CHART
            FROM EMP
            START WITH MGR IS NULL
            CONNECT BY PRIOR EMPNO = MGR
            ORDER SIBLINGS BY ENAME;

    8. PIVOT 절과 UNPIVOT 절
        - PIVOT은 행을 열로 변환해주는 기능을 수행.
        1) 기본 구문
            SELECT *
            FROM (기준 테이블)
            PIVOT (
                집계함수(집계대상칼럼)
                FOR 피벗컬럼 IN (피벗값1, 피벗값2,...)
            );

        2) PIVOT 활용 예제
            - 부서별, 직무별 사원 수 피벗 테이블
            SELECT * 
            FROM (SELECT DEPTNO, JOB FROM EMP)
            PIVOT(
                COUNT(*)
                FOR JOB IN ('CLERK' AS CLERK, 'MANAGER' AS MANAGER, 'ANALYST' AS ANALYST, 'SALESMAN' AS SALESMAN)
            )
            ORDER BY DEPTNO;

        3) UNPIVOT절 개념 및 문법
            - PIVOT의 반대 기능으로, 열을 행으로 반환 

            - 피벗된 테이블을 다시 원래 형태로 변환
            SELECT * 
            FROM (피벗된 테이블 또는 서브쿼리)
            UNPIVOT (
                EMP_COUNT
                FOR JOB_TYPE IN (CLERK, MANAGER, ANALYST, SALESMAN)
            );

    9. 정리 및 핵심 포인트
        1. 서브쿼리 위치(SELECT/FROM/WHERE/HAVING)마다 역할이 다르다 - 인라인 뷰는 복잡한 조인 대신 임시 테이블처럼 활용하면 가독성이 크게 향상됨.
        2. 집합 연산자는 칼럼 수/데이터형이 일치해야 하며, UNION ALL이 UNION보다 빠르지만 중복을 제거하지 않는다. 마지막 ORDER BY는 전체 결과에 한 번만 작성한다.
        3. ROLLUP은 계층적 합계, CUBE는 모든 조합 합계, GROUPING SETS는 선택적 합계를 만든다.
        4. 윈도우 함수는 행을 지우지 않고 통계을을 추가한다. ORDER BY만 있고 PARTITION BY가 없으면 전 행을 한 그룹으로 본다.

[3장 관리구분]
    1. DML(데이터 조작어)
        1) DELETE와 TRUNCATE의 차이점
            [DELETE]
            - 행 단위로 데이터를 삭제
            - 각 행을 개별적으로 삭제하므로 상대적으로 느림
            - 각 삭제 작업을 트랜잭션 로그에 기록
            - 트랜잭션 내에서 롤백이 가능
            - WHERE절을 사용하여 특정 조건의 데이터만 삭제 가능
            - 인덱스를 유지

            [TRUNCATE]
            - 테이블 구조를 유지한 채 모든 데이터를 한번에 제거
            - 전체 테이블을 한 번에 비우므로 일반적으로 더 빠름
            - 최소한의 트랜잭션 로그만 생성
            - 일반적으로 롤백이 불가능
            - WHERE절을 사용할 수 없으며, 항상 전체 테이블을 비움
            - 인덱스를 재설정

        2) MERGE 문
            - MERGE문은 데이터의 삽입, 업데이트, 삭제 작업을 하나의 명령문으로 처리할 수 있도록 도와주는 명령어.
            - 기본 형식
                MERGE INTO 타깃_테이블 타깃(별칭)
                USING 소스_테이블 소스(별칭)
                ON (타깃.조건_칼럼 = 소스.조건_칼럼)
                WHEN MATCHED THEN
                    UPDATE SET 타깃.칼럼1 = 소스.칼럼1, ...
                WHEN NOT MATCHED THEN
                    INSERT (칼럼1, 칼럼2,...)
                    VALUSE (소스.칼럼1, 소스.칼럼2, ...);

            - 예시
                MERGE INTO EMP_MNG M
                USING EMP E
                ON (M.EMPNO = E.EMPNO)
                WHEN MATCHED THEN 
                    UPDATE SET
                        M.SAL = E.SAL,
                        M.COMM = E.SAL 
                WHEN NOT MATCHED THEN 
                    INSERT (EMPNO, ENAME, JOB, MGR, HIREDATE, SAL, COMM, DEPTNO)
                    VALUES (E.EMPNO, E.ENAME, E.JOB, E.MGR, E.HIREDATE, E.SAL, E.COMM, E.DEPTNO);

            - 이 예시에서는 EMP_MNG와 EMP 테이블에서 EMPNO가 일치하는 행이 있을 경우, EMP 테이블의 SAL 값을 EMP_MNG 테이블의 SAL과 COMM 칼럼에 UPDATE 함.
            - 일치하지 않는 EMP 테이블의 행들은 EMP_MNG 테이블에 새로운 행으로 INSERT됨.

    2. DDL (데이터 정의어)
        1) 참조 무결성 옵션
            - 외래 키를 사용할 때 참조 무결성을 유지하기 위한 욥션을 지정할 수 있음.
                ● ON DELETE CASCADE : 부모 테이블의 행이 삭제되면 자식 테이블의 참조하는 행도 함께 삭제
                ● ON DELETE SET NULL : 부모 테이블의 행이 삭제되면 자식 테이블의 참조하는 열을 NULL로 설정
                ● ON DELETE SET DEFAULT : 부모 테이블의 행이 삭제되면 자식 테이블의 참조하는 열을 기본값으로 설정
                ● ON DELETE NO ACTION : 부모 테이블의 행을 삭제하려고 할 때 자식 테이블에 참조하는 행이 있으면 삭제 불가
                
            - 예시
                CREATE TABLE CHILD_TABLE_CASCADE (
                    CHILD_ID NUMBER PRIMARY KEY,
                    PARENT_ID NUMBER,
                    CONSTRAINT FK_PARENT_CASCADE FOREIGN KEY (PARENT_ID)
                        REFERENCES PARENT_TABLE (PARENT_ID) ON DELETE CASCADE
                );

        2) ALTER TABLE
            - 주요 기능 예시
                - 칼럼 추가
                ALTER TABLE EMP ADD PHONE_NUMBER VARCHAR2(15) NOT NULL;

                - 칼럼 삭제
                ALTER TABLE EMP DROP COLUMN PHONE_NUMBER;

                - 칼럼명 변경
                ALTER TABLE EMP RENAME COLUMN NAME TO FULL_NAME;

                - 데이터 타입 변경
                ALTER TABLE EMP MODIFY SALARY NUMBER(10,2);

                - 제약 조건 추가
                ALTER TABLE EMP ADD CONSTRAINT CHK_SALARY CHECK (SALARY > 0);

                - 제약 조건 삭제
                ALTER TABLE EMP DROP CONSTRAINT CHK_SALARY;

                - 기본값 설정
                ALTER TABLE EMP MODIFY JOIN_DATE DATE DEFAULT SYSDATE;

        3) DROP TABLE과 TRUNCATE TABLE의 차이점
            [DROP TABLE]
                - 테이블 구조와 데이터 모두 삭제
                - 일반적으로 복구 불가능
                - 인덱스, 트리거, 제약 조건 등 모두 삭제
                - 테이블 공간 반환

            [TRUNCATE TABLE]
                - 데이터만 삭제, 구조 유지
                - 일반적으로 복구 불가능
                - 인덱스, 트리거, 제약 조건은 유지
                - 테이블 곤간 초기화
